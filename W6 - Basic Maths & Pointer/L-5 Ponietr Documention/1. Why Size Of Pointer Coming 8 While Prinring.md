# Why Pointer Size Was Coming 8 While Printing?

## 📌 Introduction

In C++, the size of a pointer often confuses beginners — especially when printing it results in the value `8`. This raises the question:

**Why is the pointer size 8 bytes?**

This README explains the reason behind the pointer size on modern systems and provides clarity on how computer architecture and memory addressing influence this behavior.

---

## 🧠 Explanation

The size of a pointer in C++ is **architecture-dependent**. On **modern systems**, especially those using the **x86-64 architecture** (64-bit systems), pointers are typically **8 bytes (64 bits)**.

Here's why:

- Each variable in memory has a **unique address**.
- A **pointer** is simply a variable that holds such an address.
- The **size of a pointer** depends on how many bits are required to store an address.

---

## 🖥️ x86-64 Architecture

The **x86-64** is a 64-bit extension of the older x86 (32-bit) architecture, introduced by Intel and AMD. It supports:

- A theoretical maximum of `2^64` bytes (16 exabytes) of addressable memory.
- This requires each memory address (and thus each pointer) to be **64 bits = 8 bytes** in size.

So, on a system with x86-64 architecture:
```cpp
#include <iostream>

int main() {
    int a = 10;
    int* ptr = &a;
    std::cout << sizeof(ptr);  // Output: 8
}
```

---

## ⚙️ Other Considerations

- Some **compilers** may add **padding** or **alignment bytes**, but this usually doesn't change pointer size.
- **Function pointers** and **data pointers** can sometimes differ in size depending on the platform.
- On older or embedded **32-bit systems**, pointers might be **4 bytes** instead of 8.

---

## ✅ Conclusion

The size of a pointer in C++ is primarily determined by the system's **memory architecture**. On most modern systems (like x86-64), pointers are **8 bytes** because they need to store **64-bit memory addresses**, allowing programs to access a much larger address space.
